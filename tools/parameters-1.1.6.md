# Anarchy 1.1.6 のパラメーター変更と地形比較

C2 ZONE104 と D2 ZONE317 では、最低Coverageを下げたことで部屋が縮小しました。生成エラーへの対処でしたが、初回の検証では元の規模との比較が不足していました。元の規模を保つなら、この2か所は見直しが必要です。

| 区画 | 変更前設定での実測 | 1.1.6での実測 |
| --- | --- | --- |
| C2 ZONE104 | Coverage 40、2エリア | Coverage 3、1エリア |
| D2 ZONE317 | Coverage 30、2エリア | Coverage 10、1エリア |

両区画では部屋素材・位置も変わっています。次元を含む82区画のうち、残る80区画の部屋素材・配置座標・生成量・エリア数は一致しました。内部の壁・階段などの細部、敵、小物、補給、照明、目標の挙動まで同じという意味ではありません。

比較は同じGTFO revision 34873・依存MOD・シードで実施。変更前側は、1.1.6の共通修正を残し、5つのメインレイアウトJSONとDimensionDataだけを旧コミット31f5257へ戻しています。完全な1.1.5配布物そのものの比較ではありません。公開済み1.1.6のデータ・タグは、この比較では変更していません。

実測結果・入力データのハッシュは [比較結果JSON](geometry-comparison-1.1.6.json)、生成検証と限界は [検証報告](../VALIDATION.md) を参照してください。元の実ゲームPNGと、設定ごとに対応させた比較ギャラリーはローカルのレビュー資料として保存しています。

## 値の読み方

- `CoverageMinMax`：生成量の目標範囲。xが最小、yが最大。平方メートルではなく、完成結果の厳密な上限でもありません。例えばD3 ZONE5は目標最大50に対して実測53です。
- `SubComplex`：区画の部屋分類。`CustomGeomorph`で指定する固定部屋素材とは別の設定です。今回分類を合わせたC1・D3では、部屋素材と配置は前後で一致しました。
- `ForceBigPickupsAllocation`：大型目標アイテムの配置枠を確保するための設定。大型アイテムの個数そのものを指定する値ではありません。
- `AllowSmallPickupsAllocation` / `AllowResourceContainerAllocation`：小型アイテム／補給箱の配置を許可します。補給量そのものを指定する値ではありません。
- `ConcurrentCluster`：trueでは子スキャンすべての条件が同時に成立した場合に進行する特殊モード。falseでは通常のクラスター動作になります。使用した依存MODは2～4個に対応し、D2の6個には以前から適用を拒否していました。個数と座標は維持しています。

## 各区画の変更

### C1 ZONE68：Refinery の固定部屋

- `SubComplex: 6 (Floodways) → 1 (Refinery)`
- `ForceBigPickupsAllocation: false → true`

固定の Refinery 素材に区画分類を合わせ、連続目標用の大型アイテムを配置できるようにした。固定部屋素材・Coverage・シードは変更していない。

実測：Coverage 20 → 20、エリア数 1 → 1。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### C1 ZONE69：Storage の固定部屋

- `SubComplex: 4 (Lab) → 2 (Storage)`

固定の Storage 素材に区画分類を合わせた。固定部屋素材・Coverage・シードは変更していない。

実測：Coverage 20 → 20、エリア数 2 → 2。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### C1 ZONE70：Storage の固定部屋

- `SubComplex: 4 (Lab) → 2 (Storage)`

ZONE69 と同じ分類の不整合を修正。固定部屋素材・Coverage・シードは変更していない。

実測：Coverage 20 → 20、エリア数 2 → 2。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### C2 ZONE104：固定スキャンの区画

- `CoverageMinMax: (20,20) → (3,20)`
- `ForceBigPickupsAllocation: false → true`

最低要求を3まで下げ、広さ不足の生成エラーを抑える目的で変更した。ただし今回の前後比較では、Coverage 40・2エリアから3・1エリアへ大きく縮小し、使用する部屋素材と位置も変わった。元の規模を保つなら、この最小値の変更は見直す必要がある。大型目標アイテムの配置も有効化。スキャン座標とシードは維持している。

実測：Coverage 40 → 3、エリア数 2 → 1。部屋素材・配置座標に変化あり。

### C2 ZONE105：アイテム・補給の配置区画

- `AllowSmallPickupsAllocation: false → true`
- `AllowResourceContainerAllocation: false → true`

小型アイテムと補給箱の配置を許可し、割り当て要求と配置禁止の矛盾を解消。補給量そのものを指定する値ではない。

実測：Coverage 32 → 32、エリア数 1 → 1。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### C2 ZONE106：広さの範囲が逆転していた区画

- `CoverageMinMax: (25,20) → (20,25)`

最小値が最大値を上回っていたため、最小20・最大25に並べ直した。

実測：Coverage 30 → 30、エリア数 2 → 2。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### D1 ZONE437：発電機用セルの区画

- `ForceBigPickupsAllocation: false → true`

大型アイテムとして扱われる発電機用セルの配置を許可・確保する設定。部屋の広さや素材は変更していない。

実測：Coverage 40 → 40、エリア数 3 → 3。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### D1 ZONE438：発電機用セルの区画

- `ForceBigPickupsAllocation: false → true`

ZONE437 と同じ大型アイテム配置の修正。部屋の広さや素材は変更していない。

実測：Coverage 53 → 53、エリア数 4 → 4。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### D1 dimension16：砂漠の異次元

- `StaticLightSettings: 0 → 18`
- `ForbidTerminalsInDimension: false → true`

照明設定を標準の有効な ID 18 に戻し、端末を使わない固定の異次元で端末生成を禁止した。18 は明るさの強さではなく照明データの参照ID。

### D2 ZONE317：最低Coverageを下げた区画

- `CoverageMinMax: (20,20) → (10,20)`

最低要求を10まで下げ、広さ不足の生成エラーを抑える目的で変更した。ただし今回の前後比較では、Coverage 30・2エリアから10・1エリアへ縮小し、使用する部屋素材と位置も変わった。元の規模を保つなら、この最小値の変更は見直す必要がある。シードは変更していない。修正後の写真はZONE317内から入口側を見たもので、扉のZONE316表示は戻り先を示す。

実測：Coverage 30 → 10、エリア数 2 → 1。部屋素材・配置座標に変化あり。

### D2 scan23：6個のクラスター・スキャン

- `ConcurrentCluster: true → false（Index 23）`

true は子スキャンすべての条件が同時に満たされたときだけ進む特殊モード。使用中の依存MODは2～4個に対応するが、このクラスターは6個のため登録を拒否していた。false で通常動作を明示。スキャン数・座標は変更していない。静止画だけでは同時進行の挙動は確認できない。

### D3 ZONE5：広さの範囲が逆転していた区画

- `CoverageMinMax: (50,40) → (40,50)`

最小値が最大値を上回っていたため、最小40・最大50に並べ直した。

実測：Coverage 53 → 53、エリア数 5 → 5。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### D3 ZONE12：出口の固定部屋

- `SubComplex: 5 (All) → 1 (Refinery)`

固定の Refinery 出口素材に具体的な区画分類を合わせた。出口の素材とシードは変更していない。

実測：Coverage 32 → 32、エリア数 1 → 1。基本の部屋素材・配置座標は一致。内部の壁・階段などの細部は写真で確認してください。

### D3 scan87：副目標のスキャン座標設定

- `MainLevelLayout: Anarchy_D3_L2 → Anarchy_D3_L1`
- `GitHub版に欠けていた D3.json を復元`

### D3 fog225：出口イベント用の霧

- `Fog_anarchy_d3_after_exit.persistentID: 224 → 225`

他の霧と重複していたIDを、イベントが参照する225へ修正。Infection 0.05など霧の内容は変更していない。通常の区画写真は出口イベント後の霧の動作確認にはならない。

## 共通修正と撮影条件

空のGameDataファイル3件の削除はMTFOの読込例外への対処です。manifestのバージョンを1.1.6とし、33件の直接依存MODを検証時点の最新バージョンに更新しています。これらは特定の区画の見た目に対応する設定ではありません。

写真はCLIのコマンドファイルをゲーム内の検証プラグインが受信し、CConsole FreecamとUnity ScreenCaptureで撮影しました。画像加工やAI生成は使用していません。開発用カメラ・描画・補助照明を使用しているため、通常プレイの暗さや霧の再現ではありません。スキャンの円を表示する写真は、登録済みスキャンをCLIから個別に起動して撮影しています。配置は変更していませんが、通常の起動順序・スキャン条件や霧のイベントの動作を証明するものではありません。

C2 ZONE104 と D2 ZONE317 は区画位置が移動したため、それぞれの室内に撮影位置を合わせています。他の地形比較は同じ視点を使用しました。生ログはアカウント・セッション情報を含むため公開しません。
